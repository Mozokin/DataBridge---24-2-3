# Функциональные и нефункциональные требования

Источник: задание КТ №3 «Конвертер и валидатор данных (DataBridge)», разделы 1–3.

| ID | Требование | Критерий приёмки |
|---|---|---|
| FR01 | Чтение CSV, JSON, XML, XLSX | Четыре входных файла распознаются по расширению |
| FR02 | CSV с заголовками и без; настраиваемый разделитель | Пример no_header.csv читается с no_header.json |
| FR03 | Валидация по JSON-конфигурации | Правила меняются без изменения исходного кода |
| FR04 | required, type, min/max чисел и дат, pattern, unique, min/max_length | Нарушения отображаются с номером записи, полем и причиной |
| FR05 | Запись в четыре формата | Любой входной формат может быть преобразован в любой выходной |
| FR06 | Маппинг и минимум три трансформации | Поля переименованы; trim, upper, lower, replace, timestamp_to_date |
| FR07 | Отклонённые записи в errors.csv | Некорректные строки не включаются в выходной набор |
| FR08 | Консольный и HTML-отчёт | Число исходных, принятых и отклонённых записей; таблица нарушений |
| FR09 | Команды convert, validate, stats | Все команды запускаются с указанными параметрами |
| NFR01 | C#; без БД; модульность | .NET 8, отдельные каталоги модулей |
| NFR02 | Понятные ошибки | Диагностика без стека для ожидаемых ошибок ввода |
| NFR03 | Не менее 15 unit-тестов | Автономный тестовый проект с отчётом PASS/FAIL |
| NFR04 | Документация и примеры | README, DOCS, configs, samples |

Объект обработки — плоская запись «имя поля → скалярное значение». Границы: не учётная система; не редактирует исходные файлы; не восстанавливает повреждённые документы.
